# Cosmos — portfolio prototype

The chosen direction: your real site's structure and content, flown through
a Milky Way galaxy. `src/` is untouched — this is a self-contained HTML
prototype to build the real thing from, not the real thing itself.

Everything here makes **zero network requests** — the artifact CSP blocks
every external host, so Three.js, GSAP, your photo, and all project images
are inlined directly into the page.

## Files

| File | What it is |
| --- | --- |
| `10-cosmos.html` | The page. Markup + CSS. Self-contained once built. |
| `10-cosmos.entry.js` | The scene: camera flight, galaxy shader, stars, destinations, shooting stars. Source — edit this, not the bundle inside the `.html`. |
| `10-cosmos.content.js` | Your bio content (skills, career, projects), mirroring `src/i18n.tsx` in EN + FR. |
| `build.mjs` | Bundles the entry + content through esbuild and inlines the result into the `.html`, plus inlines GSAP and the generated image assets. Idempotent — rebuild as often as you like. |
| `gen-assets.mjs` | Downscales the real site images (`src/assets/images/...`) into small WebP data URIs. Your originals total 27+ MB; the generated set is ~150 KB. |
| `.serve.mjs` | A read-only static file server for local viewing. |
| `_assets.json` | Generated by `gen-assets.mjs` — the actual image data. Regenerate after changing any source image. |

## Viewing it

```bash
node prototypes/.serve.mjs
```

Then open <http://localhost:4321/10-cosmos.html>. Append `?motion=full` to
bypass a reduced-motion OS setting during testing (see below).

## After editing

```bash
node prototypes/build.mjs 10-cosmos.html
```

If you changed a source image, regenerate the asset manifest first:

```bash
node prototypes/gen-assets.mjs
node prototypes/build.mjs 10-cosmos.html
```

## What it does

Real site structure — nav, hero, expertise, career, projects, contact,
footer — mirroring `Navigation.tsx`, `Main.tsx`, `Expertise.tsx`,
`Timeline.tsx`, `Project.tsx`, `Contact.tsx`, `Footer.tsx`. The EN/FR toggle
retranslates every section exactly like the live site.

Scroll flies the camera between four fixed destinations — the hero has none,
since the avatar and halo already anchor that section. The camera **never
rotates** — always faces `-Z`, translation only — and each leg between
destinations moves along exactly one cardinal axis (right → down → left →
up), so no two directions ever happen at once. A constant forward drift runs
underneath the cardinal steps, which is what makes it read as flying rather
than sliding.

Each destination is a different kind of object, so arriving somewhere feels
specific: a globular cluster (5,200 stars) at Expertise, an emission nebula
at Career, a constellation that draws itself in at Projects, and an orbiting
binary at Contact. Presence is a tight falloff
curve — one destination clearly owns the screen at a time, rather than two
neighbours diluting each other.

The sky is a from-scratch galaxy shader: a core bulge that's wider as well as
brighter, branching dust lanes that absorb light, and unresolved star
granulation (the actual "milk" in Milky Way) layered under a resolved star
field with round cores and diffraction spikes. A final grade desaturates
every pixel toward neutral by default and only lets blue back in where real
galaxy structure is, so open sky reads black rather than a uniform wash.

Subtle shooting stars appear only in the hero, gated to the same presence
value the hero region itself would have had — a few per minute, capped at
0.55 opacity, a quick fade-in/hold/fade-out rather than a constant streak.

Palette is royal blue, black and white throughout — verified by sampling the
rendered framebuffer at every destination (blue channel ≥ green ≥ red).

## Motion and accessibility

- `prefers-reduced-motion` is respected: the scene renders one static frame,
  parked at the hero position, with no animation loop running at all.
- A `?motion=full` / `?motion=reduced` URL override lets you preview either
  path without changing your OS setting — useful because this preview
  environment itself reports reduced motion, which is why testing here
  requires the query param.
- A small in-page toggle appears (bottom-right) whenever the OS setting is
  active, so a real visitor can opt into full motion without touching system
  settings.

## Test seams

The entry script exposes a few `window.__cosmos*` functions for verification
without a visible browser (this environment's preview pane doesn't
composite frames, so `requestAnimationFrame` and GSAP's ticker are both
paused — these seams let you drive a frame and read state by hand):

- `__cosmosRender()` — force one synchronous frame.
- `__cosmosFlight` — the `{ p }` object driving scroll position; set `.p`
  directly (0–1) to jump anywhere in the flight.
- `__cosmosInfo()` — current region, camera position/rotation, drift depth.
- `__cosmosMeteors()` / `__cosmosForceMeteors()` — read shooting-star state,
  or force them all to fire immediately instead of waiting out their
  natural random delay.
- `__st` / `__gsap` — the ScrollTrigger and GSAP instances, for driving
  scroll-linked tweens to completion in a paused environment.

These are harmless in production but should be stripped if this becomes the
real site.

## Known gaps for a production build

- **~900 KB per load** — Three.js and GSAP are inlined whole because the
  prototype has to be one self-contained file. A real build should import
  them as normal modules so bundling can tree-shake and code-split them.
- **No webfonts** — everything is system font stacks, since the artifact CSP
  blocks font CDNs. A real build should load your actual display face.
- **Real site images are unoptimized.** `gen-assets.mjs` proves the
  opportunity (27 MB → 150 KB) but that pipeline should become a real build
  step, not a one-off prototype script.
